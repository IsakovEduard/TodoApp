# Todo Task Management Service

**Tech stack:** Java 17 · Spring Boot 3.5 · Spring Web · Spring Data JPA · Spring Security (JWT) · H2 · Caffeine cache · OpenAPI 3 / Swagger UI · Maven · Docker · React 19 · TypeScript · Vite · Redux Toolkit / RTK Query · Tailwind CSS · Vitest

## Overview

A REST service for managing personal task lists. Users register, authenticate with a JWT, and manage their own tasks through a secured HTTP API. Each user sees and modifies only their own data.

The API is contract-first: endpoints and models are defined in an OpenAPI specification (`src/main/java/com/todo/controller/api/task_management.yaml`), and controller interfaces are generated from it at build time. The code is layered into controller, business (application and domain services), and repository packages.

## Features

- **Authentication:** user registration and login (`/auth/register`, `/auth/login`) and current-user lookup (`/auth/me`); passwords stored hashed; stateless JWT authentication on all other endpoints. Requests without a valid token receive `401`.
- **Task management** (`/task-management`):
  - Create a task (title, description, urgency, due date)
  - Get a task by id
  - List tasks, optionally filtered by id, status, or urgency
  - Update task characteristics (title, description, due date, urgency, status); invalid fields are rejected
  - Delete one or more tasks by id
- **Per-user data isolation:** every task operation is scoped to the authenticated user.
- **Caching:** in-memory Caffeine cache for tasks (max 5,000 entries, 30-minute expiry).
- **Error handling:** centralized exception handler mapping not-found, unauthorized, and forbidden cases to HTTP responses.
- **API documentation:** Swagger UI generated by springdoc.
- **Persistence:** file-based H2 database with auto schema update; H2 console enabled at `/h2-console`.
- **Web UI** (`frontend/`): responsive React app served by the same Spring Boot jar, usable on desktop and phone browsers. It covers registration, login and logout (with automatic return to login when the session expires); listing tasks with status and urgency filters, sorting, and an overdue highlight; creating and editing tasks; marking several tasks completed or deleting them at once; and a light, dark or system color theme that is remembered between visits.- **Deployment:** multi-stage Dockerfile and `docker-compose.yml` with a persistent data volume. The Maven build installs its own Node.js, builds the UI and bundles it into the jar.
- **Tests:** backend unit and integration tests (services, caching, HTTP status codes, security) and frontend tests (Vitest, Testing Library, MSW).

## Running

The JWT signing secret is required and is read from the `JWT_SECRET` environment variable (at least 32 characters). Without a valid secret the application fails to start. Token lifetime is `app.jwt.expiration` (default `1h`).

**Docker:** copy `.env.example` to `.env`, set `JWT_SECRET` in it, then run:

```bash
docker compose up --build
```

**Quick start on Windows:** run `scripts\start-dev.cmd` (double-click it, or run it from any terminal). It checks Java and the port, builds the UI, starts the app with the `dev` profile and opens the browser when it is ready. Options: `-Port 9090`, `-SkipFrontend` (faster, UI not rebuilt) and `-NoBrowser`. Stop it with Ctrl+C. Only one instance can run at a time because they share the dev database.

**Local development:** use the `dev` profile, which supplies a fixed, non-secret key and stores data in `./data/todo-dev` (git-ignored). Never use it in production.

```bash
./mvnw spring-boot:run -Dspring-boot.run.profiles=dev
```

In **PowerShell** the argument must be quoted, otherwise Maven reports `Unknown lifecycle phase ".run.profiles=dev"`:

```powershell
.\mvnw.cmd spring-boot:run "-Dspring-boot.run.profiles=dev"
```

In IntelliJ, set the active profile to `dev` in the run configuration. To use a real secret locally instead, set `JWT_SECRET` (bash: `export JWT_SECRET='...'`, PowerShell: `$env:JWT_SECRET = '...'`).

Note: without the `dev` profile the datasource path is `/app/data/todo-db` (the Docker location); override `spring.datasource.url` when running outside Docker.

The service listens on `http://localhost:8080` and serves the web UI at the same address. API clients obtain a token via `POST /auth/login` and send it as `Authorization: Bearer <token>`. Sample requests are in `src/main/resources/test.http`.

**Frontend development** (hot reload): start the backend with the `dev` profile, then in another terminal:

```bash
cd frontend
npm install
npm run dev      # http://localhost:5173, API calls are proxied to port 8080
npm test         # frontend tests
npm run api:generate   # regenerate the typed API client after changing the OpenAPI spec
```

Node.js `^22.22.2`, `^24.15.0` or `>=26` is required for these commands. The Maven build downloads its own Node.js, so `./mvnw verify` needs no local installation. Use `-DskipFrontend` to skip the frontend build and tests when working on the backend only.
